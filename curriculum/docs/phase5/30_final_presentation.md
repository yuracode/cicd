##  目標

- 自分の個人制作を 5 分で通しで発表（録画 or 対面）できる
- 自分で採点基準に沿ってセルフ評価できる
- 30コマ全体を振り返り、**次に学ぶこと** を自分で決められる

##  導入

### 今回の流れ

| 時間 | 内容 |
|------|------|
| 0:00〜0:10 | 発表環境の準備（録画 or 誰かを前に） |
| 0:10〜0:30 | 本番発表（できれば録画） |
| 0:30〜0:50 | 自己採点・振り返り |
| 0:50〜0:90 | 次に学ぶことの決定・ポートフォリオ仕上げ |

### 発表の相手（自由に選ぶ）

一人で完結させるため、発表の相手は次のいずれかを選ぶ。

- **自分自身に向けて録画**（画面録画 + Webカメラ or 音声のみ）
- 友人・家族・メンター1人を相手に対面
- SNS / 勉強会 / LT 会で公開発表
- 就活・進学用のポートフォリオ動画として撮影

> **録画を残すのがおすすめ。** 30コマ分の成果を動画で残しておくと、後日の就活・進学・転職で直接使える。

### 発表中に自分に課すルール

- **公開URLとGitHubを必ず開いて始める**：言葉だけで逃げない
- **詰まったポイントを必ず話す**：完璧な話より具体的な苦労話のほうが刺さる
- **質疑の想定問答** を前もって3つ用意（「なぜこのアプリ？」「一番難しかったのは？」「次作るなら？」）

##  本題

### 1. 本番発表タイム（4〜5分）

コマ29で作った原稿とスライドに沿って、通しで発表する。録画する場合は録画ボタンを押してから開始。

発表が終わったら、次に進む前に **一度深呼吸して休憩** する。振り返りは疲れていると表面的になる。

### 2. セルフ採点シート

次の採点表に、自分で点数を付ける。**甘く付けない**。配点100点満点。

| 観点 | 配点 | 自己採点 |
|------|------|---------|
| デモが動く（公開URL） | 20 |  |
| CI/CDパイプラインが構築されている | 20 |  |
| テストが存在しPASSしている | 15 |  |
| READMEが整っている | 15 |  |
| 発表内容が分かりやすかったか | 15 |  |
| 時間を守れたか | 10 |  |
| 工夫・オリジナリティ | 5 |  |
| **合計** | **100** |  |

60点未満の観点があれば、後日1項目ずつ直す。全項目80点を超えたら、ポートフォリオとして公開して OK。

### 3. 自問自答ワーク

発表を終えた直後に、次の問いに文字で答える。**頭の中で完結させず、必ず書き出す**。

```markdown
## 自問自答メモ

1. 一番伝えたかったことは何か？
2. それは伝わったか／伝わらなかったか？（相手がいれば反応、録画なら見返した印象）
3. 自分が一番苦労したポイントは？
4. 30コマ前の自分に「これだけは教えたい」ことは？
5. 次に作るなら、どんなアプリ？
```

### 4. 30コマで身についたことチェック

### 5. 次に学ぶこと

このコースの続きとして、興味に応じて挑戦してほしい領域：

**① フロントエンドを深める**

- **TypeScript**：大きなアプリでは必須レベル
- **Next.js**：Reactベース。SSR・API・SEO・ルーティングが揃う
- **状態管理**：Zustand / Jotai / Redux Toolkit
- **CSSフレームワーク**：Tailwind CSS / CSS Modules

**② バックエンドに手を伸ばす**

- **Node.js + Express / Hono**：自分でAPIを書く
- **Supabase / Firebase**：BaaS でDBと認証が手軽に
- **Prisma**：型安全なDBアクセス

**③ CI/CD・DevOps を深める**

- **E2Eテスト**：Playwright でブラウザを自動操作
- **Docker**：環境差をコンテナで封じる
- **Terraform / IaC**：インフラもコード化
- **モニタリング**：Sentry でエラー監視、GA4 で利用状況

**④ 学習の習慣化**

- 毎月1つ小さなアプリを公開する（発表アプリをひたすら改善でもOK）
- 仕事でコードを書く前に、自分のプロジェクトで試す
- 知らないキーワードが出たら深追いする

### 6. 修了メッセージ（自分への手紙）

**この教材で身についた本当のもの：**

- **React を書ける** ことより、
- **「書いたコードが自動で検証されて公開される」仕組みを構築できる** こと

現代の開発現場では、**コーディング能力と同じくらい「開発体験を設計する力」** が重要。

Phase 1 の `hello-react` から始めて、自動テスト・自動デプロイまで持って来れたのは、業界に出て行く上で大きな武器。

### 7. ポートフォリオとして公開する

- 気に入った他のOSSや他人のアプリには Star を付ける。GitHub は **使われているほうが評価される** 仕組み

### 課題（最終・修了後も続く）

#### 基礎課題（必須）

1. **成果物4点セット** を1箇所にまとめる：① 公開URL、② リポジトリURL、③ 発表スライドPDF、④ 振り返りコメント（300字以上：学んだこと・次にやりたいこと）。自分のポートフォリオサイト / README / Notion などに集約する
2. **自分の発表を1文で振り返る**：「一番伝えたかったことは◯◯で、それは伝わった／伝わらなかった」

#### 応用課題（推奨・修了後1ヶ月以内）

3. **1ヶ月後に自分のアプリを見直す**。不具合があれば1個だけ直してPRを出す（技術は使わないと錆びる → **使い続ける仕組み** を作る）
4. **家族・友人・勉強会仲間に自分のアプリを見せる**。説明できるか試す。説明できなければ、それは自分の理解不足のサイン
5. **次の小さなアプリのアイデア** を1つ持って、リポジトリの骨組み（README＋Vite初期化）だけでも作っておく
6. **Issue を1つ立てる**：自分のアプリに「次はここを直したい／追加したい」を1個Issue化して残す。将来の自分への手紙

#### チャレンジ課題（挑戦・修了後3ヶ月以内）

7. **発展技術のどれかに1つ手を出す**（1つだけでOK）：
   - **TypeScript** 化：`.jsx` を `.tsx` に移行、型を付ける
   - **Next.js** 移行：App Router 構成に書き換える
   - **バックエンド追加**：Node.js + Express、Hono、Fastify いずれかで簡易API
   - **E2Eテスト**：Playwright で1本書く
   - **Docker化**：Dockerfile を書いてローカルコンテナで動かす
   - **IaC（Infrastructure as Code）**：Terraform / Pulumi で Vercel プロジェクトを定義

8. **OSSコントリビュートに挑戦**：自分が使っているライブラリ（React / Vite / Vitest 等）のREADMEの誤字修正・翻訳など、**どんな小さいPR** でもOK。mergeされた経験は強い自信になる

9. **ポートフォリオサイト** を作る：このアプリを含む自分の成果物一覧ページ。就活／進学／転職で使える形にまとめる

10. **技術ブログを1記事書く**：「React + CI/CD をゼロから30コマで学んだ話」「Vitest の使い方で一番詰まったこと」など、**学んだことを外に出す** ことで自分の知識として定着する（Qiita / Zenn / Medium / 個人ブログ 何でも可）

> **狙い：** 「修了＝ゴール」ではなく **「修了＝次のスタートライン」**。課題に期限を設けることで、習慣として続けやすい形にする。
